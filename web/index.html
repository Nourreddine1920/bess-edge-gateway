BESS Edge Gateway

Modbus → edge gateway → mutual-TLS MQTT → cloud · multi-day iron-air storage, simulated –
What is real here: command signing and verification use Ed25519 through your browser's WebCrypto, and the 7-check command guard is a line-by-line port of gateway/gateway.py. What is modelled: Modbus, TLS handshakes, the broker, battery physics (illustrative iron-air parameters) and the synthetic price and wind series. The full Python stack (Mosquitto, pymodbus, SQLite buffer) is in the repo and runs locally with ./demo.sh start.

What I would change for production

    

      
    
        
  • Keys in hardware: secure element or TPM, zero-touch provisioning, offline root CA, short-lived certs with rotation and revocation.
    • 
        
  • Secure boot and OTA: signed images, A/B partitions, automatic rollback, staged canary rollouts (RAUC, SWUpdate or Mender on Yocto).
    • 
        
  • Protocols: IEC 61850 and IEC 60870-5-104 toward the EMS and TSO, OPC UA where needed, Sparkplug B for MQTT payloads.
    • 
      

      
    
        
  • Cloud: managed broker, time-series database, alerting, a full audit log of every command tied to a user.
    • 
        
  • Edge autonomy: a signed schedule with a validity window so the site keeps trading through long WAN outages, with local safety limits always winning.
    • 
        
  • Standards: IEC 62443 zones and conduits, EU Cyber Resilience Act, NIS2.
